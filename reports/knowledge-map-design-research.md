## 研究记录概述

2. 成熟知识图谱 / 思维导图 / 图可视化项目。

## 一、指定六个设计网站的研究记录

### 1. https://beautifului.dev

- 访问日期：2026-10-10
- 研究页面：首页（组件集合式展示）
- 观察到的视觉特征：

  - 流式文本 + 行内来源。

  - 任务状态行：解析/建图/失败等长任务反馈。
- 是否适合本项目：
  - 适合作为课程问答、证据卡片、审阅工作流的交互参考。
- 是否可以直接复用：
  - **目前仅建议借鉴交互模式。** 未核实许可证/源码许可，不能在未确认前复制实现。
- 许可证与来源：
  - 页面未在本次访问中提供清晰许可证文本；来源是官网首页。
- 需要改造的部分：
  - 把通用 AI 产品语境替换为课程学术场景；来源卡片需带课程/课堂/页码/章节定位。

## 三、成熟知识图谱/思维导图/可视化项目的研究记录

### 思维导图/层级结构

- React Flow / XYFlow（mind map 示例 + 布局文档）：React 优先，自定义节点与交互能力强，布局需另接引擎。适合做课程节点卡片式界面。
- Markmap：适合从 Markdown 大纲生成层级视图，适合内容团队/只读展示。
- Mermaid mindmap：文本语法生成层级，官网标为实验性，不宜作为稳定核心画布。
- Mind Elixir：框架无关 JS 思维导图核心，开箱层级/编辑/展开状态较好；语义多关系仍需验证。
- jsMind：BSD，易集成，传统兼容路径清楚；复杂关系能力较弱。

### 通用节点画布

- React Flow / XYFlow：自定义节点、拖拽/缩放/平移、多选、MiniMap、Controls 等开箱能力强。
- Cytoscape.js：图模型/查询/分析强，多布局生态，适合关系探索与邻居展开。
- AntV X6：图编辑/业务级交互底座，适合定制编辑器。
- AntV G6：图可视化与分析框架，布局/交互/渲染选择丰富，适合关系探索成为核心时。
- Excalidraw：白板/自由表达，适合草稿/协作，不适合作为结构化主画布。

### 自动布局

- Dagre：简单 DAG/树起点，速度优先，易集成。
- ELK.js：配置能力强、层级/端口/边路由能力强，复杂度更高，适合“需要时再加”。
- D3 Hierarchy：层级数据变换模块，适合单根层级表达（树/treemap/partition/pack），不适合节点尺寸差异大且跨层边复杂的场景。

### 初步候选排序

1. React Flow / XYFlow + Dagre（快速验证层级 + 编辑式课程节点）。
2. React Flow / XYFlow + ELK.js（复杂关系/边路由/局部视图增强）。
3. G6 或 Cytoscape.js（关系探索/大图/邻居展开优先时对照测试）。
4. Mind Elixir（树编辑优先、低框架耦合时）。

**关键判断：** 课程数据是“层级 + 语义多关系”的混合体，不应把所有需求塞进一个纯思维导图模型。最好把层级作为主导航，把关系作为独立边/视图。

## 四、成熟知识管理产品的研究记录

- Obsidian Graph View：全局图 + 局部图（可调关系深度），节点大小反映引用，搜索/隐藏/分组着色，Backlinks 提供段落级上下文。
- Tana Outliner：可展开层级大纲、节点页、命令菜单/搜索查询、Supertag 类型/字段、多种视图、大纲/表格/卡片。
- Heptabase：白板/卡片/段落标注/来源集中管理，组织结构按课程/主题/知识点逐级展开。

共同解决的核心导航问题：

1. 先缩小范围，再展示关系。
2. 全局与局部两种尺度。
3. 关系要有语义或可追溯上下文。
4. 视图是不同的入口，不一定是不同的数据。
5. 探索之后要能回到内容本身。

对本项目建议：

- 层级承担主导航，关系图承担补充探索。
- 把包含、前置、相关、支持等关系区分编码。
- 来源与上下文是知识点的一部分，不应藏在地图之外。
- 用过滤和逐层展开控制密度，而非单纯缩放。

## 五、本阶段结论（供 M2 使用）

- UI 层：shadcn/ui 作为基础底座可能性最高；beUI 与 Transitions.dev 提供交互/动效参考；Beautiful UI 提供来源/审阅/任务状态参考；Rare UI 保留为局部参考；niceui.com 无法访问。
- 技术路线：不宜预先锁死单一画布引擎；候选是 React Flow/XYFlow + 布局引擎、G6/Cytoscape、Mind Elixir。本项目前端是零构建 Vanilla JS，若引入新依赖或框架，必须单独考虑许可证、体积、加载顺序与“零构建”约束的兼容性。
- 信息架构：课程→主题→知识点为主导航，语义关系为独立边/视图，来源可追溯是关键。
- 下一步：M2 应明确产品方向与技术路线，并在动手前实测课程端点与真实数据。

## 六、本项目实测后的补充结论（2026-10-10，验收）

1. 结论已写：
   - 实测课程数据（见审计第12节）显示：真实课程的知识点目前是扁平的，`knowledge_memberships` 为 0、`knowledge_relations` 为 0，且合并/审核语义位于名为 `conflicts`/`course_conflicts`/`course_review_records` 的表体系中，而非 V2 曾假设的 `merge_proposals`。
   - 最大真实课程（Gestió de Projectes）目前有 61 个知识点、2 个材料、6 条证据、28 个课堂（session），但没有主题成员关系，也没有知识关系。
   - 因此，本次重设计的第一个可用产品视图不应假定“课程 → 主题 → 知识点”的富层级数据存在，而应先做**知识点画布 + 搜索定位 + 详情/证据追溯 + 材料地图**，并在设计研究中优先保留能在扁平数据上工作的模式（表格/卡片/来源卡片/差异/任务状态），而不是一开始就为课程主题层级建模。
   - 对应的研究结论调整：
     - shadcn/ui 的表格/Tabs/Sidebar/命令面板/Skeleton 方向，比“课程大纲树组件”更先匹配 MVP。
     - Beautiful UI 的差异表/任务行/审阅参考，比“课程大纲层级浏览”更先有用。
     - 思维导图专用库（Mind Elixir/jsMind）若作为 MVP 入口，要么等主题/层级数据就绪，要么接受当前数据下画布不如表格/卡片视图实用。
   - 选型结论不变，但落地方式变了：**先实现能在现有扁平数据上就能用的探索视图，再随着主题/关系数据演化扩展为层级地图。**
2. 验收结果：
   - 上述结论**已写**进 `reports/knowledge-map-design-research.md` 第6节（见文件尾部）。
   - 本节不再重复罗列，仅保留验收标记：结论已落盘，且与审计第12节一致。
