# TASK-77 — Automatic AI Material Processing & Real-World Multimodal Pilot

## 0. 任务定位

TASK-76 已完成 AI Understanding Layer 的基础建设：

```text
Evidence
→ deterministic chunking
→ AI Provider
→ structured candidates
→ evidence grounding
→ dedup / merge / conflict
→ confidence policy
→ KnowledgePoint
→ Review
```

但目前存在一个关键产品缺口：

> AI 分析仍然需要用户手动点击 `AI Analyze` 才会执行。

这与 Classroom Assistant 的最终产品目标不一致。

本任务的目标不是继续增加抽象层或测试数量，而是完成真正的：

```text
上传学习材料
→ 自动识别
→ 自动处理
→ 自动 AI 分析
→ 自动总结
→ 自动提取 KnowledgePoint
→ 自动建立 Evidence Trace
→ 自动进入知识库
→ 低置信度 / 冲突进入 Review
```

最终用户不应该再承担“自己读原文 → 自己总结 → 自己添加知识点”的主要工作。

# 4. 自动触发 AI

这是本任务第一核心修改。

当前：

```text

    ↓
deterministic processing
    ↓
完成
```

改为：

```text
process_material()
    ↓
deterministic ingestion
    ↓
Evidence created
    ↓
AI enabled?
    ├── NO → finish
    └── YES
          ↓
      AI analysis
          ↓
      Knowledge extraction
          ↓
      Review / auto accept
```

必须保持 Feature Flag：

```text
CLASSROOM_AI_ENABLED=true
```

当关闭：

```text
CLASSROOM_AI_ENABLED=false
```

必须保持 TASK-76 以前的行为。

# 5. 不要让 AI 阻塞基础材料处理

必须区分：

```text
Material ingestion
```

和：

```text
AI understanding
```

AI 服务失败不能导致：

```text
Material = failed
Evidence = lost
```

正确状态应该是：

```text
Material
    ↓
Ingestion: SUCCESS
    ↓
Evidence: SAFE
    ↓
AI: FAILED
    ↓
Retry available
```

例如：

```text
Material status:
READY

AI status:
FAILED

Reason:
HTTP 429
```

不能把整个 Material 标记成无法使用。

# 14. Idempotency

重复执行：

```text
Analyze
Analyze
Analyze
```

不能产生：

```text
KnowledgePoint × N
Evidence × N
Summary × N
```

必须保证：

```text
same material
same pipeline
same model
same prompt
```

可以安全重复执行。

如果某一个 chunk 失败：

```text
90% complete
10% failed
```

Retry 时只需要处理失败部分。
