# 知识地图设计系统（M3 草案，现实版）

- 状态：初稿，待真实课程数据上的原型验证
- 用途：为知识地图提供一组共享的语义 token 与视觉规则，避免在不同视图/节点/面板里重复硬编码颜色、间距、圆角和字号。
- 范围：知识点画布/探索/材料/列表视图共用，同样可被现有课程/材料/详情视图吸收。
- 现实前提：现有课程数据可能首先是“扁平知识点 + 材料 + 证据”，而非富层级课程主题树。设计系统必须既能支持节点画布/列表/详情，也能在未来有主题/关系数据时自然扩展。

---

## 1. 品牌基调

目标：

- Professional。
- Academic。
- Calm。
- Precise。
- Modern。
- 视觉可辨识。
- 高可读性。

避免：

- 过度渐变。
- 满屏玻璃拟态。
- 满屏发光边框。
- 每个节点不同颜色。
- 无节制卡片堆叠。
- 默认所有元素都是圆角胶囊。
- 所有内容塞进深色卡片。

出发点不是复制任何外部设计系统的默认风格，而是从它们借用可验证的组件/交互/动画模式，再用自己的语义标签重新组织。

---

## 2. 语义设计 token

### 2.1 颜色角色

- `--bg`：页面底色。
- `--surface`：卡片/节点基底。
- `--surface-2`：次级面板/侧栏/组头。
- `--surface-3`：悬停/选中/强调面。
- `--border`：默认分隔线。
- `--border-strong`：强调边框/键盘 focus ring。
- `--text`：主正文。
- `--text-muted`：次级说明。
- `--text-soft`：占位/辅助。
- `--ok`：确认/完成/可用。
- `--warn`：提醒/待验证/不确定。
- `--bad`：错误/断链/失败。
- `--accent`：产品强调色（选中、主要入口、品牌锚点）。
- `--accent-soft`：强调色软底（用于搜索命中/高亮面）。
- `--on-accent`：强调色上的文字。
- `--on-ok`：ok 色上的文字。
- `--relation`：语义关系边/标签（如果存在）。
- `--hierarchy`：层级边/结构线（如果存在）。

颜色应按角色使用，而不是在每个组件里直接写`--accent`的浅色版/深色版。

### 2.2 层级

- 底色层级：`bg` → `surface` → `surface-2` → `surface-3`。
- 文字层级：`text` → `text-muted` → `text-soft`。
- 强调层级：普通 → hover → selected/focus → accent。
- 面板/节点层级不靠颜色 alone，而是靠间距、边框、阴影和位置共同表达。

### 2.3 阴影与边框

- 默认卡片：轻边框 + 极弱阴影。
- 面板/侧栏：更明显一点的边框或分隔线。
- 选中/聚焦态：边框强化 + focus ring，不靠“发光”传递状态。
- 节点：可重复的统一边框/圆角规则，不要每个节点自定义风格。

### 2.4 圆角

- 小控件：小圆角。
- 卡片/面板：中等圆角。
- 节点：统一但不过度圆滑。
- 按钮/标签不默认都是胶囊。

### 2.5 状态语义（现实前提）

- 如果当前课程数据没有主题/关系，则不应在默认 UI 里渲染空层级或空关系边；相应 token（`--hierarchy`/`--relation`）可以保留，仅在真实数据存在时才激活。
- 状态色用于表示“已验证/待验证/冲突/错误”等语义，不用于装饰不同类型的节点。

### 2.6 接入外部参考的边界

- 可借用 shadcn/ui 的组件基础与语义 token 的**组织方式**，但不照搬其默认金融/仪表盘风格。
- 可借用 beUI 的交互（课程树、键盘导航、侧栏折叠/抽屉、搜索式多选、表格虚拟化方向）。
- 可借用 Transitions.dev 的过渡与状态切换节奏（骨架屏、accordion、手风琴展开、滑动视图切换、reduced-motion）。
- 可借用 Beautiful UI 的来源卡片/审阅/任务状态表达思路，但必须替换为课程语境并加入课程/课堂/页码/章节定位。
- 所有外部参考落地前，须单独核实许可证/来源/署名要求（如 Rare UI 的 Commons Clause/署名要求、Transitions.dev 的 core/Pro 区分、beUI/Beautiful UI 的源码许可）。

## 3. 排版

### 3.1 字体选择原则

- 优先保证中文、西班牙语、加泰罗尼亚语都能清晰排版。
- 重音/特殊字符/混合语言标题必须能正常显示。
- 不依赖“某一种颜值字体”；可读性 > 风格。
- 窄屏换行、长标题截断/折行规则要明确。

### 3.2 类型比例

- 标题。
- 次标题。
- 正文。
- 小字/元信息。
- 技术字（ID/hash/session path 等）用等宽。
- 强调字。

### 3.3 行高与长度

- 正文行高足够易读。
- 长段描述不要拉太宽。
- 节点内文本行数受控：默认不把完整正文塞进节点。

---

## 4. 间距

- 间距使用统一刻度（如 4/8/12/16/24/32/48...）。
- 节点内部：统一垫距。
- 面板内部：统一垫距。
- 视图之间的边距/分割：统一规则。
- 不要在每个视图里各写一套魔数间距。

---

## 5. 节点与面板尺寸

### 5.1 节点（现实版：第一阶段可以是知识点节点，不一定有层级）

- 节点不是缩小版详情页。
- 第一阶段节点可能展示：标题、所属材料/证据数量、状态 badge、重要度（如果有）、选中/聚焦态。
- 如果后续有主题/子概念/关系数据，再新增层级/展开折叠/关系边语义。
- 节点类型可区分为不同尺寸/密度，但不要靠颜色族分类别。

### 5.2 面板

- Detail Panel、Materials Panel、Explorer Panel 共享排版与内边距。
- 面板宽度有默认值，并在窄屏下重新排布。
- 面板内变化不应触发整体画布布局重算。

### 5.3 画布/视口

- 节点尺寸、画布内边距、节点间距都有明确默认。
- 初始视图不靠缩小整个图来“适配屏幕”；应默认呈现一个可读的起始集。
- 放大后也应可读。

---

## 6. 图标

- 使用统一图标风格。
- 每个图标有明确语义。
- 同一操作在不同位置不用不同图标。
- 没有 Tooltip 的纯图标按钮不作为主要操作。
- 不依赖颜色作为唯一状态提示。

## 7. 动画

### 7.1 允许的动画类型（示例）

- 面板平滑展开/折叠。
- 卡片尺寸变化。
- 搜索结果聚焦。
- 详情切换。
- 内容渐入。
- 轻量状态反馈。
- 数字变化。
- 列表与详情之间的过渡。

### 7.2 禁止的动画模式

- 节点每次点击都全图重排。
- 大量节点同时弹跳。
- 长时间阻塞操作的动画。
- 忽略 `prefers-reduced-motion`。

### 7.3 节奏

- 一般交互动画控制在约 120–240ms。
- 复杂布局过渡可更长，但必须实测。
- 关键状态变化不能只靠动画表达。

## 8. 多语言排版

- 西班牙语/加泰罗尼亚语标签通常比中文长。
- 节点标签、组头、工具栏文字要能适应更长文本。
- 术语保留原文，必要时括号附中文解释。
- 语言标注明确（es / ca），中文仅作输出/解释层。

## 9. 状态系统

- 空态、加载态、错误态、部分成功态都要有专门表达，不能是空白页。
- 成功与否不只看一个颜色。
- 不确定内容要有明确标注（如待验证/推测/不确定类语义），不编造。

## 10. 响应式与窄屏

- 大屏：侧栏/地图/详情合理分区。
- 中等屏：调整列宽/面板顺序。
- 窄屏：不强行压缩三栏；可切到目录/列表/单节点详情/局部关系视图。
- 移动端若支持，优先保证阅读与操作，而不是强行展示完整地图。

---

## 11. 验收

- 真实浏览器里看。
- 真实课程数据上看。
- 多语言下看。
- 默认视图不能是拥挤节点集合。
- 搜索能定位。
- 详情能追溯到来源与证据。
- 地图与列表都能完成任务。

## 12. 与 M2 方案的衔接

- M2 方案（`docs/knowledge-map-product-spec.md`）明确了第一个最小产品视图是**知识探索优先**（知识点 canvas + 搜索定位 + 详情/证据追溯 + 材料地图）。
- 设计系统相应细节（节点尺寸、面板宽度、 token、动画）应先服务于这一阶段的视图，而不是一开始就为完整层级课程地图建模。
- 当真实课程数据准备好（例如主题成员关系、知识关系补全），再把层级/关系语义扩展进同一套 design system。
