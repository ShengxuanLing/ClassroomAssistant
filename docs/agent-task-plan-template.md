# Loomind · Agent 任务计划书模板

> 这是给**任何** agent（codex / cline / opencode / freebuff / workbuddy）执行任务时用的计划书模板。
> 澳龙每次接到用户需求，会按这个模板写一份 `docs/task-xxx-<slug>-plan.md`，然后把它交给目标 agent。
>
> **写计划书的人（澳龙）**：把下表每一节都填满，现象必须带 `文件:行` 证据，推断必须标「推断」。
> **执行任务的人（目标 agent）**：先读 `docs/agent-handoff-context.md`，再读本计划书，
> 只做计划书明确要求的事，没要求的**一律不加**。

---

## 计划书正文模板（复制后逐节填写）

```markdown
# TASK-XXX 任务计划书 —— <一句话标题>

- 日期：YYYY-MM-DD
- 基线：<git commit hash，动手前自己 `git log --oneline -5` 再核对一次>
- 依据：<用户原话 / 截图 / 上一份报告的结论>
- 状态：**待实施**。本文只是计划书，不含任何代码改动。
- 交付物：<明确：一份文档？改哪些文件？不新增什么？不留什么备份？>

> **纪律声明**
> 1. 本文把**实测**（带 `文件:行` 证据）与**推断**分开写，推断一律标「推断」。
> 2. 实施者**不得扩大范围**：§N 明确列了「不在本次范围」清单。
> 3. 用户原话是唯一依据，文档没要求的一律不加。

---

## 0. 一句话目标

<用一句话说清：改什么、为什么、不碰什么。>

## 1. 需求原文 → 可验收的拆解

| # | 用户原话 | 拆解成什么 | 验收判据（可复核） |
|---|---|---|---|
| R1 | <原文摘录> | <具体到可执行> | <能客观判真假的观察项> |

## 2. 现状（全部实测，带证据）

<逐点写清当前代码的真实行为，每一条带 `文件:行` 或命令输出。>
<不知道的**漂标「推断」**，禁止把记忆当事实——动手前自己核实。>

## 3. 目标设计

<为每个 R 写：改什么、绝不改什么、交互/数据流长什么样。>
<明确列出「改名禁区/不动的对象」：机器标识、已落盘数据、被测试断言的串。>

## 4. 逐文件改动清单

| # | 文件 | 位置 | 改什么 |
|---|---|---|---|
| 1 | `<路径>` | `:<行号>` | <精确描述> |

## 5. 守卫 / 测试面（谁会被这次改动碰到）

<列出会红/要同步的守卫：ui_audit.js、ui_render_check.js、test_*.py、i18n 三语表、WEB_FILES 引用等。>

<可勾选清单，全部勾上才算 DONE。>

<逐条：不跑全量回归、不 git add -A、不删测试、不把测试数据混入真实课程、不捏造性能数字……>

<明确列出，避免实施者顺手扩大范围。>
```

## 写作要点（澳龙专用，写给自己的）

1. **现状必须先实测再写**。拿到需求后，先 `grep` / `read` 相关源文件，把真实行为钉下来。
   只凭记忆写现象，到了别的 agent 手里就会改错。
2. **每个现象带 `文件:行`**。这是让「懂一点的 agent」和「不太懂的 agent」都对得上的锚点。
3. **验收判据可复核**。让最不懂的 agent 也能照着一条条对，而不是靠感觉。
4. **明确「不做什么」**。freebuff / cline 之所以改坏，一大半是"顺手"扩大了范围或改了不该改的。
5. **把环境坑写进交接上下文，不重复写进每份计划书**（见 `agent-handoff-context.md`）。
   计划书只写本次任务特有的事实。

## 交付流程

1. 澳龙读懂需求 → 实测现状 → 按模板写 `docs/task-xxx-<slug>-plan.md`。
2. 把计划书交给目标 agent，并叮嘱：**先读 `docs/agent-handoff-context.md`，再读计划书，再动手**。
3. agent 干完后，澳龙按「验收纪律」核验：只信 `git diff` + `ui_audit.js` 跑完 + 定向测试，不信自述。
4. 把一个 agent 反复踩的新坑，回写进 `agent-handoff-context.md`，让下一个人不重复踩。
