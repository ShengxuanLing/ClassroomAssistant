# 知识地图产品方案（M2）

- 状态：初稿，待真实课程数据验证
- 依据：`reports/knowledge-map-redesign-audit.md`、`reports/knowledge-map-design-research.md`、`reports/knowledge-map-technology-evaluation.md`

## 1. 核心选择（更新：紧贴实测数据）

### 现实前提

- 本任务目标仍是最终做出一个成熟的课程知识地图产品，但**第一个可用视图必须基于现有真实数据**。
- 实测显示当前课程数据更接近“扁平知识点 + 材料 + 证据”，而非“已分层课程主题树”（见 `reports/knowledge-map-redesign-audit.md` 12 节）。
- 因此本方案不再从“课程 → 主题 → 知识点”的富层级地图开始，而是从**知识点如何被浏览/追溯/串联**起步，再随着数据演化逐渐加入主题/关系结构。

### 产品方向

- 核心仍然是：理解课程知识、在知识之间导航、从知识追溯到材料与证据。
- 但第一个最小产品形态更接近**知识探索视图优先**：
  - 用真实材料/证据组织知识点。
  - 用搜索定位知识点。
  - 用详情面板阅读与追溯。
  - 在此基础上，再逐步加入层级/关系/主题结构（当数据存在时）。

### 技术路线（初步）

- 第一期仍然倾向保持现有零构建 Vanilla JS 前端，并以成熟布局/交互参考为指导重新实现：
  - View Model 分离。
  - 布局对“扁平知识点”也要可读（不假设层级存在）。
  - 搜索定位、聚焦、选择、详情面板。
  - 材料/证据追溯视图。
- 如果后续数据准备好了，或者 PoC 显示某成熟图可视化库更合适，再评估引入（如 Cytoscape.js / G6 / React 图栈）。

## 2. 五个工作视图（现实版）

### 2.1 Overview（课程总览）

- 课程名、课程 ID（仅在技术必要处）。
- 知识点总数、材料数、证据数、带冲突/待审核语义的项数。
- 按真实数据显示——比如如果没有主题，就不显示“主题数”或明确说明“暂无主题结构”。
- 统计全部来自真实 API，不编造。

### 2.2 Map / Canvas（知识点视图）

- 当前阶段不强求一开始就是层级地图；可以先是**知识点画布**。
- 默认不把全部知识正文塞进节点。
- 支持选中、聚焦、搜索高亮。
- 如果未来有主题/关系数据，再升级为层级+关系视图。

### 2.3 Explorer（知识探索 / 详情）

- 选中知识点后显示：
  - 标题。
  - 陈述/摘要（如果有）。
  - 关联材料。
  - 证据数量与来源定位。
  - 状态（validation/review/needs_verification 等）。
- 关系展示只在真实关系存在时呈现，不虚构 AI 解释。

### 2.4 Materials（材料地图 / 材料视角）

- 从材料反查其贡献的知识。
- 材料可点击进入材料详情。
- 材料与知识点之间的关联基于真实数据。

### 2.5 List（知识目录）

- 搜索、排序、筛选。
- 展示来源数量/证据数量/状态。
- 支持从列表定位到画布或详情。

## 3. 数据语义保护

保留后端事实：

- Canonical Knowledge。
- Knowledge Candidate/合并候选语义。
- 合并/冲突/审核语义（以当前 schema 的 conflicts 与 review_records 体系为准）。
- Knowledge Relation（如果存在）。
- Material。
- Evidence。
- 课程/课次管理。
- 材料上传与查看。
- 多语言机制。

禁止：

- 把 related 自动转成 parent-child。
- 为了布局整齐制造不存在的层级。
- 把候选/冲突当成已确认知识。
- 编造知识点/证据/来源。

## 4. 搜索与导航

- 全局搜索覆盖知识点、主题、材料以及可检索的摘要内容（如果数据支持）。
- 选中结果后：
  1. 切换到正确视图。
  2. 展开必要的父级路径（如果存在）。
  3. 定位目标。
  4. 高亮目标。
  5. 打开详情或提供明确打开操作。

## 5. 视觉与交互底线

- 品牌风格：Professional / Academic / Calm / Precise / Modern / 可读性高。
- 动画服务于反馈与空间连续性，而不是炫耀。
- 默认 120–240ms 级交互动画，复杂布局过渡可更长但须实测。
- 支持 `prefers-reduced-motion`。
- 颜色不是唯一状态提示。

## 6. 验收问题

产品完成后必须能回答：

> 与普通课程文件列表 / AI 摘要列表相比，这个知识地图为什么更值得学生使用？

预期答案至少包含：

- 跨材料融合后的知识点视图（如果数据支持）。
- 真实知识关系（如果存在）。
- 来源追溯。
- 更快的知识定位。
- 更好的课程结构理解（未来随着主题/关系数据就位）。
